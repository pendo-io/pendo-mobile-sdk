# Kotlin Multiplatform with native UI

This guide integrates Pendo into both targets of a Kotlin Multiplatform (KMP) app that uses platform-native UI: Jetpack Compose or Views on Android, and SwiftUI or UIKit on iOS.

> [!NOTE]
> These instructions use Pendo Android and iOS SDK `3.14.x`.

> [!IMPORTANT]
> Native-UI KMP apps integrate the Pendo Android and iOS SDKs in their respective application targets. For shared Compose UI, use the [Compose Multiplatform guide](/other/compose-multiplatform.md).

Pendo setup, session management, UI tracking, and Pairing Mode stay in the native application targets because they depend on each platform's lifecycle and view hierarchy. Shared (`commonMain`) code does not need a Pendo dependency. If shared business logic needs to emit Track Events, see [Optional shared-code bridge](#optional-shared-code-bridge).

## Android integration

Add Pendo to the Android application module, such as `androidApp`. Do not add it to `commonMain`.

### Android requirements

- Android Gradle Plugin `8.0` or higher
- Kotlin `1.9.0` or higher
- Java `11` or higher
- `minSdk 21` or higher
- `compileSdk 35` or higher
- For Jetpack Compose, `androidx.compose.ui:ui` `1.5.0` or higher
- If your app uses Room, `androidx.room` `2.6.0` or higher

### Install the Android SDK

KMP projects normally use Gradle Kotlin DSL (`.gradle.kts`). Groovy dependency syntax does not compile in these files.

1. Add the Pendo repository to `dependencyResolutionManagement` in `settings.gradle.kts`, or to the Android application module's repositories:

    ```kotlin
    repositories {
        exclusiveContent {
            forRepository {
                maven {
                    url = uri("https://software.mobile.pendo.io/artifactory/androidx-release")
                }
            }
            filter {
                includeGroup("sdk.pendo.io")
            }
        }
        google()
        mavenCentral()
    }
    ```

2. Add Pendo to the Android application module's `build.gradle.kts`:

    ```kotlin
    dependencies {
        implementation("sdk.pendo.io:pendoIO:3.14.+") {
            isChanging = true
        }
    }
    ```

3. Configure the supported SDK versions if the module does not already meet them:

    ```kotlin
    android {
        compileSdk = 35

        defaultConfig {
            minSdk = 21
        }
    }
    ```

If you use ProGuard with `{Android SDK Location}/tools/proguard/proguard-android-optimize.txt`, add `!code/allocation/variable` to the `-optimizations` line in `proguard-rules.pro`.

### Set up Pendo and start an Android session

Find the API key in the Pendo UI under **Settings > Subscription settings > select an app > App Details**.

> [!IMPORTANT]
> Projects generated by the [Kotlin Multiplatform wizard](https://kmp.jetbrains.com) might not include an Android `Application` subclass or the `INTERNET` permission. Add them when they are missing.

1. Create an `Application` subclass in the Android application module:

    ```kotlin
    import android.app.Application
    import sdk.pendo.io.Pendo

    class MainApplication : Application() {
        override fun onCreate() {
            super.onCreate()

            Pendo.setup(
                this,
                "YOUR_API_KEY_HERE",
                null, // PendoOptions; use only if instructed by Pendo Support
                null, // Optional PendoPhasesCallbackInterface
            )
        }
    }
    ```

2. Register the class and permissions in the Android application module's `AndroidManifest.xml`:

    ```xml
    <manifest xmlns:android="http://schemas.android.com/apk/res/android">
        <uses-permission android:name="android.permission.INTERNET" />
        <!-- Recommended so the SDK can monitor connectivity. -->
        <uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />

        <application
            android:name=".MainApplication"
            ...>
            ...
        </application>
    </manifest>
    ```

3. Start a session after the app can identify the visitor, for example in an Activity, Fragment, or Android authentication flow:

    ```kotlin
    import sdk.pendo.io.Pendo

    Pendo.startSession(
        "VISITOR-UNIQUE-ID",
        "ACCOUNT-UNIQUE-ID",
        mapOf("age" to 27, "country" to "USA"),
        mapOf("Tier" to 1, "Size" to "Enterprise"),
    )
    ```

`visitorId` identifies the user, while `accountId` associates that user with a company or group. The two metadata maps contain visitor and account attributes. Starting a session ends the previous mobile session, if one exists, and retrieves guides for the new visitor and account.

> [!TIP]
> To start an [anonymous visitor](https://support.pendo.io/hc/en-us/articles/360032202751), pass `null` or `""` as the visitor ID. Call `startSession` again to identify the visitor or switch visitors.

### Track Android UI

For classic Android Views, follow the standard native setup above. The Compose-specific modifiers in this section do not apply.

For Jetpack Compose:

- Compose Navigation 2 is supported with Pendo SDK `3.7.0` or higher. Compose Navigation 3 is supported with Pendo SDK `3.12.0` or higher.
- Add `Modifier.pendoTag("unique-id")` when a stable identifier is needed for Feature tagging, for a click Pendo does not automatically recognize, or to anchor a tooltip to a non-clickable Composable. Tags are case-sensitive. Set `mergeDescendants = true` when descendant semantics are needed for better identification; its default is `false`.

    ```kotlin
    Button(
        onClick = ::submit,
        modifier = Modifier.pendoTag(
            tag = "checkout-submit-button",
            mergeDescendants = true,
        ),
    ) {
        Text("Submit")
    }
    ```

- When using Compose Navigation with a drawer or modal bottom sheet, add `Modifier.pendoStateModifier(componentState)` to the component. Update the drawer or sheet state when dismissing it so Pendo stops detecting it as the current Page.

    ```kotlin
    ModalBottomSheet(
        sheetState = sheetState,
        modifier = Modifier.pendoStateModifier(sheetState),
        onDismissRequest = {
            scope.launch {
                sheetState.hide()
            }
        },
    ) {
        // Sheet content
    }
    ```

### Configure Android Pairing Mode

Pairing Mode enables [Page tagging](https://support.pendo.io/hc/en-us/articles/360033609651-Tagging-Mobile-Pages#HowtoTagaPage) and [guide testing](https://support.pendo.io/hc/en-us/articles/360033487792-Creating-a-Mobile-Guide#test-guide-on-device-0-6). Find the scheme ID under **Settings > Subscription settings > select an app > App Details**.

Add this activity inside the `<application>` element in the Android application module's `AndroidManifest.xml`:

```xml
<activity
    android:name="sdk.pendo.io.activities.PendoGateActivity"
    android:launchMode="singleInstance"
    android:exported="true">
    <intent-filter>
        <action android:name="android.intent.action.VIEW" />
        <category android:name="android.intent.category.DEFAULT" />
        <category android:name="android.intent.category.BROWSABLE" />
        <data android:scheme="YOUR_SCHEME_ID_HERE" />
    </intent-filter>
</activity>
```

> [!NOTE]
> This activity is only used by Pendo's pairing mode (page tagging and on-device guide testing) and isn't required by your production app. If you prefer not to expose it in release builds, add it to a debug-only manifest (`src/debug/AndroidManifest.xml`) instead of the main manifest. Pairing will then be available only in debug builds.

### Verify the Android integration

1. Run the app from Android Studio with Logcat open.
2. Look for `Pendo SDK was successfully integrated and connected to the server.`
3. In the Pendo UI, open **Settings > Subscription Settings**, select the app, and open **Install Settings**.
4. Complete **Verify Your Installation** and confirm the app is shown as **Integrated**.

## iOS integration

Add Pendo to the iOS application target in Xcode, such as `iosApp`. Installing the native SDK is independent of how the shared Kotlin framework is linked.

> [!WARNING]
> CocoaPods has announced that its registry will become read-only in December 2026. Pendo will stop publishing new SDK versions to CocoaPods, while existing versions remain available. Swift Package Manager is recommended. See the [CocoaPods to SPM migration guide](/migration-docs/cocoapods-to-spm-migration.md).

### iOS requirements

- iOS deployment target `11` or higher
- Swift compatibility `5.7` or higher
- Xcode `14` or higher
- SwiftUI codeless support requires iOS `15` or higher; SwiftUI screen navigation tracking is available from iOS `13`

### Install the iOS SDK

Use one of these package managers:

#### Swift Package Manager (recommended)

1. In Xcode, select **File > Add Package Dependencies**.
2. Enter `https://github.com/pendo-io/pendo-mobile-sdk`.
3. Select **Up to Next Minor Version** from `3.14.0` and add the `Pendo` product to the iOS app target.

#### CocoaPods

Add the following to the iOS app's `Podfile`, then install the pods:

```ruby
pod 'Pendo', '~> 3.14.0'
```

### Set up Pendo and start an iOS session

Find the API key in the Pendo UI under **Settings > Subscription settings > select an app > App Details**.

A wizard-generated KMP iOS app commonly uses the SwiftUI lifecycle and has no `AppDelegate`. Add one for Pendo setup and connect it to the SwiftUI app.

1. Create the `AppDelegate`:

    ```swift
    import UIKit
    import Pendo

    class AppDelegate: NSObject, UIApplicationDelegate {
        func application(
            _ application: UIApplication,
            didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]? = nil
        ) -> Bool {
            PendoManager.shared().setup("YOUR_API_KEY_HERE")
            return true
        }
    }
    ```

2. Attach it to the SwiftUI app with `UIApplicationDelegateAdaptor`:

    ```swift
    import SwiftUI

    @main
    struct iOSApp: App {
        @UIApplicationDelegateAdaptor(AppDelegate.self) var appDelegate

        var body: some Scene {
            WindowGroup {
                ContentView()
            }
        }
    }
    ```

An existing SwiftUI `App.init()` can remain alongside `UIApplicationDelegateAdaptor`. For a UIKit lifecycle app, call `setup` from `application(_:didFinishLaunchingWithOptions:)`, or from `scene(_:willConnectTo:options:)` when the app owns setup through a `SceneDelegate`.

3. After `setup`, start a session when the app can identify the visitor:

    ```swift
    let visitorData: [String: any Hashable] = [
        "age": 27,
        "country": "USA",
    ]
    let accountData: [String: any Hashable] = [
        "Tier": 1,
        "Size": "Enterprise",
    ]

    PendoManager.shared().startSession(
        "VISITOR-UNIQUE-ID",
        accountId: "ACCOUNT-UNIQUE-ID",
        visitorData: visitorData,
        accountData: accountData
    )
    ```

`visitorId` identifies the user, while `accountId` associates that user with a company or group. The two metadata dictionaries contain visitor and account attributes. Starting a session ends the previous mobile session, if one exists.

> [!TIP]
> To start an [anonymous visitor](https://support.pendo.io/hc/en-us/articles/360032202751), pass `nil` or `""` as the visitor ID. Call `startSession` again to identify the visitor or switch visitors.

### Track SwiftUI

Pendo automatically tracks navigation performed with standard SwiftUI navigation and presentation components. Rendering a different view conditionally within the same Page is not necessarily a navigation event.

- Apply [`.trackPage(pageId: "page-id")`](/api-documentation/native-ios-apis.md#viewtrackpage) when a dynamic view represents a distinct Page that standard navigation does not expose. Use an ID that is unique across the app.
- Apply [`.pendoTag("unique-id")`](/api-documentation/native-ios-apis.md#viewpendotag) to provide a stable Feature identifier, especially for tappable container views or `Menu` and `.contextMenu` triggers.

    ```swift
    Button("Submit") {
        submit()
    }
    .pendoTag("checkout-submit-button")
    ```

- If Pendo does not recognize a custom clickable view, apply `pendoRecognizeClickAnalytics()`. The native accessibility equivalent is:

    ```swift
    .accessibilityElement(children: .combine)
    .accessibilityAddTraits([.isButton])
    ```

Pendo Feature tagging uses iOS accessibility information. Keep accessibility identifiers, labels, hints, and traits stable and meaningful.

### Configure iOS Pairing Mode

Pairing Mode enables [Page tagging](https://support.pendo.io/hc/en-us/articles/360033609651-Tagging-Mobile-Pages#HowtoTagaPage) and [guide testing](https://support.pendo.io/hc/en-us/articles/360033487792-Creating-a-Mobile-Guide#test-guide-on-device-0-6). Find the scheme ID under **Settings > Subscription settings > select an app > App Details**.

1. In Xcode, open **App Target > Info > URL Types** and add:
   - **Identifier:** `pendo-pairing`
   - **URL Scheme:** the scheme ID from the Pendo UI

2. Handle the URL in the `AppDelegate`:

    ```swift
    func application(
        _ app: UIApplication,
        open url: URL,
        options: [UIApplication.OpenURLOptionsKey: Any] = [:]
    ) -> Bool {
        guard url.scheme?.range(of: "pendo") != nil else {
            return false
        }

        PendoManager.shared().initWith(url)
        return true
    }
    ```

3. A SwiftUI lifecycle app must also forward URLs from `onOpenURL`:

    ```swift
    @main
    struct iOSApp: App {
        @UIApplicationDelegateAdaptor(AppDelegate.self) var appDelegate

        var body: some Scene {
            WindowGroup {
                ContentView()
                    .onOpenURL { url in
                        if url.scheme?.range(of: "pendo") != nil {
                            _ = appDelegate.application(
                                UIApplication.shared,
                                open: url,
                                options: [:]
                            )
                        } else {
                            // Handle other application URLs here.
                        }
                    }
            }
        }
    }
    ```

If the app uses `SceneDelegate`, forward Pendo pairing URLs with `scene(_:openURLContexts:)` instead:

```swift
func scene(
    _ scene: UIScene,
    openURLContexts URLContexts: Set<UIOpenURLContext>
) {
    guard let url = URLContexts.first?.url,
          url.scheme?.range(of: "pendo") != nil else {
        return
    }

    PendoManager.shared().initWith(url)
}
```

### Verify the iOS integration

1. Run the app from Xcode with the console open.
2. Look for `Pendo Mobile SDK was successfully integrated and connected to the server.`
3. In the Pendo UI, open **Settings > Subscription Settings**, select the app, and open **Install Settings**.
4. Complete **Verify Your Installation** and confirm the app is shown as **Integrated**.

## Optional shared-code bridge

Keep setup, session management, UI tracking, and Pairing Mode platform-owned. If shared business logic needs to emit Track Events, inject a small Pendo-agnostic interface into `commonMain`.

> [!IMPORTANT]
> This bridge follows the same native SDK ordering: call `setup`, then `startSession`, before sending Track Events. Track calls made before a session starts are ignored.
>
> Keep `iosMain` Pendo-free. Kotlin/Native cannot directly call the Swift Pendo SDK without custom cinterop bindings. The recommended approach is to implement this interface in Swift and inject it into shared code.

1. Define the interface and injection point in `commonMain`:

    ```kotlin
    interface PendoAnalytics {
        fun track(
            event: String,
            properties: Map<String, Any>,
        )
    }

    object SharedAnalytics {
        private var analytics: PendoAnalytics? = null

        fun setImplementation(impl: PendoAnalytics) {
            analytics = impl
        }

        fun trackSharedEvent(action: String) {
            analytics?.track(
                event = "shared_$action",
                properties = mapOf("origin" to "commonMain"),
            )
        }
    }
    ```

Use interop-safe property values such as strings, numbers, and booleans. Avoid passing custom Kotlin objects in Track Event properties.

2. Implement it in the Android application target and inject it after `Pendo.setup`:

    ```kotlin
    import sdk.pendo.io.Pendo

    class AndroidPendoAnalytics : PendoAnalytics {
        override fun track(event: String, properties: Map<String, Any>) {
            Pendo.track(event, properties)
        }
    }

    // After Pendo.setup(...)
    SharedAnalytics.setImplementation(AndroidPendoAnalytics())
    ```

3. Implement it in the Swift iOS application target and inject it from `AppDelegate.application(_:didFinishLaunchingWithOptions:)` after `PendoManager.shared().setup(...)`:

    ```swift
    import Shared // Replace with the framework baseName from shared/build.gradle.kts.
    import Pendo

    final class IOSPendoAnalytics: PendoAnalytics {
        func track(event: String, properties: [String: Any]) {
            let nativeProperties: [AnyHashable: Any] = Dictionary(
                uniqueKeysWithValues: properties.map {
                    (AnyHashable($0.key), $0.value)
                }
            )

            PendoManager.shared().track(
                event,
                properties: nativeProperties
            )
        }
    }

    // In AppDelegate, after PendoManager.shared().setup(...)
    SharedAnalytics.shared.setImplementation(
        impl: IOSPendoAnalytics()
    )
    ```

The Swift import must match the Kotlin framework's `baseName`; it is not always `Shared`. Kotlin declarations can also export to Swift with different class, method, and parameter names depending on the Kotlin version and framework configuration. Use Xcode autocomplete or the generated framework interface to confirm the names and labels in your project.
